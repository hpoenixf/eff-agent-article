# 从多个专家到一份研究：多层 Agent 协作的下一站（2026 展望）

**多找几位 AI 专家，只有在它们补上了关键证据、纠正了一条重要理由时才值得。** 如果最后只是多了几份报告、几次模型调用和更长的等待，协作就没有证明自己的价值。

先看一个教学场景：用户已经持有几只基金，准备增加一只半导体 ETF，理由是“多买一只可以更分散”。但他半年后需要一笔现金，也不清楚新旧基金是否买了很多相同的公司。这里不是让专家投票买不买，而是查清理由是否成立、资金能否使用、哪些条件还不知道。

本文保留 **2026 年 10 月 24 日的设计展望**，不是一次真实投资研究的运行记录，也不是多专家已经胜过单个研究助手的效果结论。10 月 25 日的观察和后续实现变化另列在文末，不把后来的进展写回当时的假设。

下文把负责用户问题与最终综合的模型称为**主研究者（Main）**，把它按需委派、独立处理局部问题的执行实例称为**研究助手（Child）**。先记住分工即可，不需要预先理解整个系统。

## 一、先弄清缺的是资料、计算，还是一个好问题

在这个基金例子里，至少有三种不同的工作：

| 缺少什么 | 应该做什么 | 对判断有什么影响 |
| --- | --- | --- |
| 原组合和候选基金的资料 | 读取获准持仓与披露，核对日期及覆盖范围 | 只看到前十大持仓，就不能声称算出了精确的全部重叠 |
| 新方案会改变多少 | 按一致口径计算买入后的现金和资产暴露 | 用现金买入与卖出旧基金换入，是两种不同方案 |
| 原理由是否站得住 | 检验“基金数量增加就更分散”等具体主张 | 即使增加了科技暴露，也不自动得到“应该买入”的结论 |

一个主研究者加合适的工具，也可能完成这三类工作。计算规则明确时，直接调用计算工具，不必让几位专家各算一遍。只有某项局部调查需要深入、某种方法能检验被忽略的条件，才考虑分工。

例如，可以让一个助手核对两份原始披露，另一个检查现金约束。但它们都应围绕同一个用户问题工作，而不是各写一篇通用的基金介绍。**委派之前，先说清希望它补上哪一个缺口。**

## 二、不同专长，不是层层增加的主管

原展望把执行专长、投资方法、多空职责和个人指引分别讨论。读资料、用不同方法分析、提出反证，是不同工作，并不意味着 Web 助手指挥 Python 助手，再由某个“投资大师”批准结果。

在当时的系统中，这些工作已有各自基础：

| 已有基础 | 在同一个任务里有什么用 |
| --- | --- |
| 通用主任务与子任务、Web/PDF/Python 工具 | 分开处理局部资料或计算，再交回结果 |
| 六种投资研究方法 | 从配置、尾部风险、长期纪律、成本等不同角度检查理由 |
| 有界多空对话 | 支持方与质疑方围绕同一条假设直接问答，不要求争出赢家 |
| 可选研究审阅助手（Research Reviewer） | 复查已有材料与计算，提出遗漏或补查建议 |
| 用户保存的专家指引 | 让一次任务使用明确版本的个人研究方法 |
| 投资论点与历史记录 | 保存原理由、证伪条件和后续修订，便于将来复核 |

这张表说明当时已有的局部基础，不是整项研究已经验收的清单。真正缺的不是第七位专家，而是这些工作能否在同一道问题里产生有效交接。

审阅助手也不是最高裁判。它可以提醒主研究者“你漏看了现金用途”，不能因此获得批准交易或否决合法正文的权力。对已经发布的答案另行生成审查报告，则是另一项需要显式请求的工作；不能把两者混成每次交付前的强制审批。

## 三、沿同一个问题，按需要增加协作

主研究者首先确认：用户是在主动增加科技配置，还是希望降低集中度？准备动用哪笔钱？随后读取获准资料、核对日期并计算变化。如果这些工作已经足以回答，就没有必要再请专家。

若“更分散”仍是一条影响决策的脆弱假设，再选择合适的方法检验它。支持方可以说明增加目标暴露的理由，质疑方检查底层重叠和现金需求。双方可以修改观点，也可以在没有新证据时提前结束。

下面保留原展望的协作图。它是一张**可选择的路径图，不是要求每项任务走完的流程，也不是当前工具参数说明**。

~~~mermaid
flowchart TD
    U[投资者提出问题] --> M[Main 确认目标与已获准资料]
    M --> A{材料足以回答当前问题?}
    A -- 是 --> H[Main 整理有依据的判断]
    A -- 否 --> B[按需委派取证与金融计算]
    B --> C{来源与计算口径可核实?}
    C -- 否 --> G[保留未知并缩小结论]
    C -- 是 --> D{需要独立金融研究方法?}
    D -- 否 --> H
    D -- 是 --> E[按需绑定合适的投资视角]
    E --> F{核心假设值得反证?}
    F -- 否 --> H
    F -- 是 --> P[可选 Bull Bear 交叉质疑]
    P --> H
    G --> H
    H --> Q{值得启动独立 Reviewer 吗?}
    Q -- 否 --> T[关联论点证据与版本]
    Q -- 是 --> V[可选 Reviewer 复查原证据与缺口]
    V --> W{Main 决定再补查吗?}
    W -- 是 --> B
    W -- 否 --> T
    T --> R[向用户发布并保留可读历史]
~~~

图中的审阅仍是可选建议。没有审阅不自动代表答案无效，收到建议也不意味着必须再开一轮研究。是否继续，应结合遗漏的重要性、已有资料、授权和剩余资源决定。

如果这条路径真正完成，用户应拿到类似下面的结果。**这是目标输出示例，不是实际运行成绩：**

> 已核实：候选基金及其持仓对应明确的披露日期；可以用本次获准数据比较一部分暴露变化。
>
> 仍有缺口：部分基金只披露前十大持仓，不能给出精确的全部重叠比例；行业占比也不能直接替代整体波动率。
>
> 理由需要修正：“多买一只就更分散”没有足够支持。若真实目标是增加科技暴露，应按那个目标另作比较。
>
> 需要确认：半年后所需现金的金额和用途。没有这些信息，不替用户假定风险承受能力，也不自动下单。

## 四、协作最容易断在四个交接处

### 算完了，别人却没有拿到原结果

“Python 助手已经算过”不足以支持报告里的一个数字。接收者需要原输入、日期、单位、计算结果和缺失范围，并且真的读到了这些材料。保存了结果、返回了引用、模型使用了结果，是不同的事实。

在我们的例子里，助手若只交回“重叠较高”，主研究者就无法判断它算的是全部持仓还是前十大。更合适的交接是可回读的原结果，加上“本次只覆盖已披露部分”。各位专家不应再凭转述各自拼出一份不同的组合事实。

### 反方说了很多，关键理由却没有改变

质疑方发出消息，不等于原主张已经被推翻。要看它挑战哪一条理由、用了什么证据，支持方实际回应了什么，主研究者最后是否解释了这个分歧。

投资论点可以经过评估后标为得到支持、受到挑战、已被推翻或暂无法判断。**根本没有评估，不能记成“评估后无法判断”。** 一条讨论消息也不能擅自改写原来保存的论点版本。

### 用户改了专家指引，旧任务跟着变了

假设任务启动时采用的是“先核对现金需求”的方法，用户后来把配置改成了另一种偏好。进行中的任务和历史记录仍需要知道当时实际用的是哪一版，不能悄悄换成同名的新内容。

指引也不是权限。写上“读取所有账户”或“永远买入”，不会增加数据访问、工具调用或交易授权。一个助手不能把未获准材料写进摘要，就让其他助手合法取得它。

### 一个助手失败，整份成果被清空

读不到一份 PDF、某个助手超时，不应撤销已经合法取得的独立结果。主研究者可以交付有明确范围的部分研究，但不能把缺失的关键材料当成不存在，更不能用漂亮的文字掩盖未完成。

审阅发现遗漏也是同样道理：它提供下一步建议，不自动决定整项任务的终态。自动审阅关闭、只执行并记录而不自动投递建议、把建议交给后续主请求，是不同运行方式；其中只记录不投递的模式仍会消耗资源，不是免费的检查。

## 五、怎样判断多一位助手值不值得

先用工具齐全的单个主研究者作对照，而不是拿一个刻意削弱的版本衬托多专家。保持原问题、资料可用范围和计算口径可比，保留失败、部分结果与费用。

| 对照路径 | 想观察的增量 | 需要一并记录的代价 |
| --- | --- | --- |
| 单个主研究者加工具 | 能否发现重要事实、检查原理由并交付 | 长上下文和可能遗漏的问题 |
| 加入按需助手 | 局部取证或计算是否更深入，成果是否真的被采用 | 委派、重复读取与交接丢失 |
| 再加入不同方法与可选多空质询 | 是否找到新的有效反证，改变一条关键理由 | 更多调用、等待和观点相互影响 |

独立审阅的作用要另外观察：是否真的执行、主研究者是否看见建议、建议有没有改变后续工作。不能把审阅发现的问题全部算成多空辩论的收益。

先判断报告本身能不能用：有没有回答原问题，日期和口径是否适用，数字能否复算，缺口是否说清。然后再看新增参与者带来了什么，是否值得额外的时间、费用和复核成本。

如果新专家只是重复已有事实，关闭它就是合理结果。没有必要再增加一个万能“专家总控”来掩盖重复委派；主研究者继续综合，原工具和任务管理逻辑继续负责执行、预算与记录即可。

## 2026-10-25 后记：安排了协作，不等于完成了交接

次日的不同真实模型任务留下了正反两面：有普通方法助手完成并被主研究者使用的样本，也有要求选择 2–3 位专家却派出 4 位、多空已配对却没有真正问答、审阅与双方开场已发生但后续唤醒和恢复仍有缺口的样本。这些不是同一批完整研究，不能相加成一个成功率。

这使我们更明确地分开三件事：“请检查另一位专家的理由”只是工作指引；收到并读过对方的原结果，才是资料交接；真正完成配对、发消息、等待和采用回复，才是通信过程。写出一个关系字段，不会自动完成后两件事。

## 现状维护：入口已经简化，效果仍需单独回答

后续统一专家实现已将**普通新任务收敛到一个可选的 `agentId`**：每个助手选择一个完整专家定义，不再同时叠加旧的执行类型、投资视角和用户配置字段。不选专家仍能进行普通研究。旧任务按原来封存的内容和身份读取，不被新入口重新解释。

六种投资方法与用户保存的专家由统一目录选择，但多空通信和受管理的审阅保留各自规则；统一名称不增加工具或账户权限。用于说明协作关系的文字，也不会自动取得另一个助手的结果、替它等待或派发。

前述部分顺序与恢复问题后来已有对应修复和限定工程验收，不能把 10 月 25 日的失败永远写成当前缺码，也不能把原失败记录改成通过。**这些进展说明特定交接能工作，不等于已经证明多专家比单个主研究者更懂投资。** 本文也不把内部系统的能力视为公开教学实现已经全部具备的功能。

回到最初的基金问题，最有用的结果不是专家名单，而是：原理由哪里成立、哪里改变，还缺哪项资料或用户确认。新增助手只有真正改变了这份回答，才值得留下。
