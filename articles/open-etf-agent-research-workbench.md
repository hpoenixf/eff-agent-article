# 从命令行到研究工作台：让一份研究下次还能接着做

<LearningPathNav />

你周一问 Agent：「这只 ETF 的跟踪表现怎么样？说明书里该看什么？」周二想补一句：「跟昨天比，有哪些变化？」第二个问题看似只是多聊一句，却要求系统知道：昨天哪份报告真的完成了、引用了什么、今天问的是不是同一件事。要是别人也用这套工作台，还要先分清这份历史属于谁。

Open ETF Agent 从命令行走到浏览器，不只是把按钮搬到网页上。[Wind 入门篇](https://hpoenixf.com/eff-agent-article/articles/open-etf-agent-wind-fund-workshop)讲的是怎么拿到口径正确的基金数据；这篇换一个问题：拿到结果之后，怎么重新打开、沿原文追问、把同一个问题留到明天，又怎么让另一个人从自己的工作区开始？下面用同一个跟踪表现问题走一遍。起步用内置示例，不用 API 密钥，也不需要真实基金数据。

## 第一次：先试试能不能找回昨天的报告

在 [v0.39.0 固定版本](https://github.com/hpoenixf/open-etf-agent/releases/tag/v0.39.0) 的仓库目录，使用 Node.js 26.8.1–26.x：

```bash
git clone --branch v0.39.0 --depth 1 https://github.com/hpoenixf/open-etf-agent.git
cd open-etf-agent
npm ci --ignore-scripts --no-audit --no-fund
npm run gui -- --project ./test-output/local-gui --port 4179
```

打开命令打印的本机地址，新建会话，选内置的模拟跟踪资料，再输入上面的问题。你会得到一份带来源的示例报告。此处的回答由离线脚本根据选中的资料生成，不会理解问题、联网取行情或调用模型；它适合练操作，不适合拿来判断 ETF 表现。

先打开「核对来源 [1]」，再复制或下载报告。然后刷新网页，或停止服务并用同一项目目录和端口重新启动。回到原会话，你还能找到原问题、已保存的正文和来源。顺手另开一个会话，写半句不发送，再切回来：浏览器的草稿属于各自会话，换另一个浏览器不会跟着过去。**草稿是下一步想问的话，历史是已经做过的研究。** 两者分开，才能既保留输入进度，又不让一次编辑悄悄改变已经完成的任务。[本地工作台用法](https://github.com/hpoenixf/open-etf-agent/blob/v0.39.0/docs/local-gui.md)

## 第二次：接着问，不等于让系统重新跑一次

如果真正想问「说明书里哪一句支持昨天的判断」，可以在 [v0.41.0](https://github.com/hpoenixf/open-etf-agent/releases/tag/v0.41.0) 的单人研究工作台里继续同一会话。默认启动仍是离线示例；使用真实模型和外部研究工具，需要按[工作台设置指南](https://github.com/hpoenixf/open-etf-agent/blob/v0.41.0/docs/local-gui-live.md)显式开启，给在线任务另建项目目录。不要把本机监听端口暴露到外网。

这版带入的是同一会话的近期问答，不是把整个历史库交给模型；界面也能展示系统记录下来的执行进度。这里有两个容易混淆的动作：**打开昨天的报告，只读原结果；发送今天的追问，才开始新工作。** 想确认昨天说了什么，先打开旧报告；只有核对现有证据还回答不了问题，才值得发起新 Run。公开发布的验收覆盖非 PDF 路径，不能用它证明浏览器 PDF 流程已经验收，也不等于托管站点已经更新。

## 第三次：把问题留给明天，把对照留在历史里

如果你每天都想看同一件事，可以把问题写成「核对这只 ETF 的跟踪表现，说明和上一次相比有哪些已被证实的变化；资料不足就指出缺口」，到 [v0.42.0 每日追踪](https://github.com/hpoenixf/open-etf-agent/blob/v0.42.0/docs/local-gui-daily-watch.md)里保存。它只在受信任的单人在线工作台使用；选好北京时间并保存设置，本身不会发起模型请求。自动执行还要由工作台和服务侧显式开启，可能使用模型额度。

关键不在「每天几点」，而在「拿哪次结果对照」。问题没改、运行权限相同，系统才会找同一追踪里最近一次可验证的完成结果。比如周二失败了，而周一报告仍能读回，周三会对照周一，并显示实际对照日期，不会把周二的失败当作「没有变化」。把问题改成「费用有没有变」则开启新基线；改回原文字也不继承那段旧对照。昨天的报告是对照，不是今天新事实的证据。

邮件是另一条可选交付路径。研究完成与邮件送达不是同一个状态：[v0.42.0 的发布记录](https://github.com/hpoenixf/open-etf-agent/releases/tag/v0.42.0)只验证了模拟 SMTP，没有证明外部邮箱收到。刚上手时，先去追踪卡片打开原会话和基线报告；不配邮件也能完成这项检查。

## 换一个人，就该从不同的工作区开始

上面的练习只有你一个人。如果另一位使用者也问同样的 ETF 问题，系统不能因为措辞一样，就让他打开你的报告。[v0.43.0](https://github.com/hpoenixf/open-etf-agent/releases/tag/v0.43.0) 增加了单独启动、按邀请创建账户的本地工作区，使用 Better Auth 和 Node SQLite。每个账户拥有自己的项目、历史和报告；退出登录后，原服务端会话会被撤销。默认离线工作台和普通安装没有变，发布也没有启用托管账户或迁移已有线上数据。只练习一份报告怎么回读，不必先装账户模块。

回到最开始的问题：要让研究下次还能接着做，先验证你能不能**重开原报告、点到它用过的原文、分清复用的是哪一次结果**。有了这个基础，再决定用追问、每日对照还是独立账户。否则页面越像工作台，你反而越难回答那句最简单的话：「我现在看到的，到底是哪一次研究？」
