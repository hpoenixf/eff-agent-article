# 多 Agent 值不值得开？我们测了启动、送达和最终收益

同一道题，主 Agent 真正派了子 Agent，答案会更好吗？2026 年 11 月 16—17 日，我们对照了 **100 次实际启动子 Agent** 的运行和对应的无子 Agent 运行，又单独比较了 **19 次实际收到 Reviewer 建议** 的运行。**平均每题多花 141 秒，已知 token 用了 2.47 倍，两轮的平均分都更低。** 逐题看，明确的计算复核出现了提分，少数读不通资料的任务则拉低了平均分。

## 普通子 Agent 实际启动的 100 次

首轮有 13 次由主 Agent 自行启动子 Agent。对首轮没有委派的另外 87 个题次，我们加上明确的委派要求重跑，87 次都实际启动了子 Agent。每次都与同一题、同一重复编号、未启动子 Agent 的运行配对。

| 实际启动方式 | 运行对数（有效评分） | 启动均分／16 | 未启动均分／16 | 分差 | 胜／平／负 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 主 Agent 自行委派 | 13（13） | 11.08 | 13.92 | −2.85 | 6／1／6 |
| 明确要求委派后重跑 | 87（86） | 14.83 | 15.24 | −0.42 | 29／30／27 |

补测时，每个题次的三份答案放在同一次盲评中。表中未启动列对应同题的关闭组。同场参与评分的首轮未委派答案平均 **15.16 分**，比补测中实际委派的答案高 **0.34 分**。补测原有 1 对评分输出无效，该对一直计入 87 对的耗时和用量，补评结果见下文。

测评使用十道冻结的合成资料题，每题重复十次。评审模型只看问题、资料和匿名答案，从正确性、覆盖、限制和完成度四项打分，满分 16 分。两轮分开列分。

### 多花了多少时间和 token？

| 配对样本 | 平均整轮耗时（启动／未启动） | 已知输入＋输出 token（启动／未启动） | 研究模型调用（启动／未启动） |
| --- | ---: | ---: | ---: |
| 首轮自行委派 13 对 | 478.98／336.36 秒（+42.4%） | 856.53／328.08 万（+161.1%） | 521／188 |
| 明确委派补测 87 对 | 328.10／187.74 秒（+74.8%） | 3,097.66／1,269.66 万（+144.0%） | 2,002／923 |
| **全部 100 对** | **347.71／207.06 秒（+67.9%）** | **3,954.19／1,597.73 万（+147.5%）** | **2,523／1,111** |

耗时从研究开始算到整轮结束，包含排队和异常终态。Token 是已返回用量的输入与输出总和，补测启动侧有 1 次模型调用缺少回执。已知新增 token 中，约 **92.5%** 来自输入。额外的 **1,412 次**模型调用里，子 Agent 占 **924 次**，主 Agent 和入口仍多用了 **488 次**。

逐对看，**92 对**有子 Agent 的一侧更慢。99 对有效评分中，**59 对**同时满足分数持平或更低、耗时更长、已知 token 更多。**35 对**得分提高，其中 **32 对**也更慢。只有 **2 对**同时做到提分、更快且 token 更少。

## 什么情况下提分，什么情况下掉分？

### 资料已经读到，子 Agent 有一道具体的题可以复算

首轮 13 次自行委派可以按首次委派时能否读到正文来拆。

| 委派当时的资料状态 | 对数 | 启动／未启动均分 | 分差 | 胜／平／负 | 已知 token 变化 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 已读到五份资料，委派计算或统计复核 | 4 | 15.75／14.50 | **+1.25** | 4／0／0 | +12.7% |
| 还没读到可用正文就委派 | 9 | 9.00／13.67 | **−4.67** | 2／1／6 | +256.9% |

统计核验题的一次运行（N07-R05）里，主 Agent 原先把缺失率对样本量的影响说反了。子 Agent 按两组各自的缺失率重新计算，给出 **394 和 373，合计 767**，主 Agent 把这组数字和修正写进了最终答案。这一对得 **16 比 15**，用了 **25 比 12** 次模型调用。这个例子能追到具体的一处修正，也能看到为复核多花了多少。

补测也能看到这个差异。首次委派前，主 Agent 已读到五份资料的 **35 对**平均高 **0.29 分**。还没读到任何可用正文的 **46 对**平均低 **1.00 分**。另有 5 对在委派前只读到部分资料。

明确委派的补测里，同一道统计核验题 **6 对赢 3、平 3**。另一道费用比较题 **9 对赢 4、平 5**。例如费用题有一对得 **16 比 13**，两边都算出约 **438 天**的成本交点。高分答案写清了这个交点依赖净值不涨跌、服务费在满一年后继续计提。该题最初由主 Agent 独立作答的版本同场也拿到 **16 分**，这个质量水平在单 Agent 运行里也出现过。

### 资料还没读通，子 Agent 接到了同一个难题

首轮落在这一组的 9 次，主 Agent 往往已经发了 **11–20 次**请求才委派。部分子 Agent 又碰到同样的定位和读取错误。组合集中度题的一次运行（N03-R08）里，两名子 Agent 回报读取受阻，主 Agent 把诊断写进答案，最终只得 **4 分**。独立作答的一侧读到了材料，算出了两组集中度和冲击损失，得 **16 分**。这次交接带回了诊断，用户要的计算没有交付。

明确委派的补测里，最明显的失分集中在两道要求重建事实的题。

| 补测题目 | 有效对数 | 委派／未委派均分 | 分差 | 胜／平／负 |
| --- | ---: | ---: | ---: | ---: |
| 多来源事故时间线 | 6 | 8.33／15.17 | **−6.83** | 2／0／4 |
| 投资者总回报和执行事实重建 | 9 | 13.89／15.22 | **−1.33** | 3／1／5 |

事故时间线有一对是 **1 比 16**。委派版只确认了读取失败，漏掉事故影响、恢复时间和请求是否完成。未委派版利用了时间戳、探活结果和供应商记录，把服务恢复与请求完成分开。总回报题也有一对是 **2 比 14**，委派版只给出通用框架，未按材料算出两种份额的回报。两道题合计少 **53 分**，补测其余 71 对合计多 **17 分**。这也解释了为什么补测有 **29 胜、27 负**，平均分仍低 **0.42 分**。差距最大的是少数答案漏掉了整段关键工作。

### 真正拉开差距的是整轮结束时读到了什么

补测 86 对有效评分中，有 **81 对**最终读到了五份资料，委派版平均 **15.48 分**，同题对照 **15.23 分**，合计多 **20 分**。其余 **5 对**都输，合计少 **56 分**。其中四次没读到任何正文，一次只读到两份。少数读取失败给平均分带来的影响，超过了多数答完的题带来的小幅收益。

开始没读到资料，也有追回来的例子。事故时间线的另一轮（N09-R07）在首次委派前没有可用正文，子 Agent 后来读到了五份资料。最终得 **15 比 14**，也避免了把一条无法归属的供应商记录当作原请求完成的证据。但总回报题也有一轮在子 Agent 读到五份资料后仍得 **14 比 16**，因为答案无依据地排除了内部费率差异。读到资料能补上事实基础，接下来还要核对用这些资料推出了什么。

## 原来失分的答案，重新评分还会输吗？

我们把原来低分的 **33 对**单独拿出来，让同一型号重新给原答案盲评。评分只看题目、冻结资料和匿名答案，仍按四项各 4 分。

| 原评分差距 | 有效对数 | 复评均分（启动／未启动） | 原分差 | 复评分差 | 复评胜／平／负 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 原来低 1–2 分 | 24 | 14.92／15.50 | −1.38 | −0.58 | 4／7／13 |
| 原来低 8–15 分 | 9 | 4.11／15.33 | −11.44 | −11.22 | 0／0／9 |
| 原来失分的样本合计 | 33 | 11.97／15.45 | −4.12 | −3.48 | 4／7／22 |

原来低 1–2 分的样本中，有 **11 对**复评后追平或反超。大幅失分的 **9 对**复评后仍全部低分。事故时间线里原来失分的 7 对复评仍全输，平均低 **11.71 分**。其中一次（N09-R06）原来 **1 比 16**，复评是 **2 比 14**。评审对具体给几分有出入，缺掉时间线和影响重建的答案依然明显落后。

此前评分输出无效的一对（N01-R01）也用原答案补评，结果是 **14 比 14**。至此 100 对各有有效评分记录。上文保留原轮次的评分表，这次只复查原失分样本和补齐缺分。

## Reviewer 建议实际送达的 19 次

Reviewer 的任务是检查已有研究的遗漏、冲突和薄弱假设。这组测试里有 19 次确认审查建议进入了主 Agent 的后续输入。下表用同一题、同一重复编号、没有 Reviewer 的答案做对照。

| 指标 | 实际收到建议 | 同题无 Reviewer | 差异 |
| --- | ---: | ---: | ---: |
| 平均分／16 | 13.21 | 13.68 | −0.47 |
| 平均整轮结束时间 | 306.59 秒 | 258.38 秒 | +48.21 秒（+18.7%） |
| 研究模型调用总数 | 477 | 246 | +231 次 |
| 已知输入＋输出 token | 645.09 万 | 391.04 万 | +65.0% |

19 对里，收到建议的一侧 **4 胜、7 平、8 负**。收到建议的一侧有 4 次模型调用缺少用量回执。

一道扣除非经常性损益的题，收到建议后答了 **15 分**，对照是 **12 分**。高分答案把几种利润口径分得更清楚，也保留了实际缺失的拆分信息。另一道时间线题，收到建议的一侧只覆盖五份来源中的一份，得了 **9 分**，对照是 **16 分**。

## 下次增加一个 Agent，先说清它要改变什么

这次实验给了我们两条具体的设计线索。已有证据时，委派可以用于复算一条关键结论。资料入口受阻时，先解决读取问题通常更切题，尤其是答案依赖多份材料拼起来的时间线。这里的题目分组来自运行记录，用来定位收益和失分出现在哪里。

任务差异尤其重要。Anthropic 在 [How we built our multi-agent research system](https://www.anthropic.com/research/multi-agent-research-system) 中，把多 Agent 的优势与可并行探索的独立方向联系起来，同时讨论了额外 token 消耗和共享上下文、任务依赖带来的限制。它们的内部任务、模型组合和评估方式与本文不同，结果不能直接横比。这提醒我们继续问：任务到底需要更大的探索范围，还是只需要把已有材料读准确？

根据这次观察，我会把委派问题写得更具体一些。

如果主 Agent 已拿到资料，需要检查费用适用条件、复算一组数字或寻找某条结论的反例，可以给子任务明确的核验对象和可检查产物。只有一句“再看看有没有问题”，就很难分清它补上了缺口，还是复述了一遍已有结论。

如果主 Agent 卡在资料入口，先查实际可用的导航和读取回执。Child 可能帮助定位，但必须观察它是否获得了可用的新证据；不能因为任务交出去了，就把原来的阻塞视为已解决。

后来沿实际请求检查这些读取问题时，我们发现系统掌握了文件位置，但发给模型的目录省略了它。单片段材料的定位入口已经修通，对真实回答的影响还有待复测。[资料明明在，Agent 为什么读不到？](agent-document-navigation-after-empty-search.md)

评估 Reviewer 时，可以先看建议是否进入了主 Agent 的后续输入，再逐题核对最终答案补上了什么。上面两道题的分差，就分别落在利润口径和材料覆盖上。

**能启动专家，说明系统具备协作能力；是否值得启用，要看它是否提供新的证据、独立核验或有效反证，被主 Agent 用上，并改善了值得改善的结果。** 时间、token 和未知费用，也都属于这个判断。

下次增加一个角色之前，先选一条希望它改善的关键结论。沿实际输入、子任务发现和最终答案核对一遍，再与关闭该角色的结果比较。这样才能知道，额外的协作究竟帮了谁、帮在哪里，以及这份帮助值不值得。
